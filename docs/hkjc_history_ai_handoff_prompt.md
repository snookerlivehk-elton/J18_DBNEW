# HKJC 歷史補充資料 AI 交付 Prompt

請先完整閱讀以下文件，並以其為唯一主規格來源執行第一版開發：

- `docs/hkjc_history_data_development_manual.md`
- `docs/hkjc_history_v1_implementation_checklist.md`
- `docs/hkjc_history_v1_task_checklist.md`
- `docs/hkjc_history_human_verification_checklist.md`
- `docs/hkjc_history_human_verification_results_template.md`

你的任務是：

- 在現有專案基礎上，完成 HKJC 歷史補充資料第一版開發。
- 以現有賽果資料庫為起點，透過馬匹歷史出賽紀錄整理待抓場次清單。
- 對每一場歷史賽事抓取該場全部馬匹資料，而不是只抓單匹馬。
- 完整打通馬匹歷史索引、場次任務生成、`incident_report`、`running_comment`、`sectional`、資料入庫、回填流程、服務 UI 的 API，以及第一版 UI。

你必須嚴格遵守以下規則：

- 第一版只抓香港本地正式賽事。
- 排除海外賽事、試閘、barrier trial 與其他非正式賽事。
- 若馬匹歷史頁存在 season 切換，必須逐季全抓。
- 只要打開某場，就要把該場全部馬匹資料一併處理。
- 所有正式資料一律只新增，不覆寫；若唯一鍵已存在則直接跳過。
- 不得刪除既有有效資料，不得以清庫、整表重建、先刪後建作為第一版策略。
- `horse_section_rank_1 ~ 6` 第一版必須保留欄位，但全部填 `null`，不得推導。
- 分段資料固定輸出 6 段；不足段數補 `null`。
- 不得自行加入 NLP、摘要生成、語意標記或進階分析功能。
- 可做小幅便利性補強與小型報表，但不得擴張主線 scope。

第一版範圍必須包含：

- script / background job / batch backfill
- API
- UI

第一版 UI 必須至少提供：

- 場次主視圖
- 馬匹主視圖
- 場次搜尋
- 馬匹搜尋
- 完整內容查看
- 手動重抓入口
- 批次任務進度頁

第一版互動與執行規則：

- UI 首頁預設先進場次主視圖。
- 競賽事件報告與沿路走勢評述以原文全文展示為主。
- 分段資料 UI 必須完整展示 6 段欄位。
- 手動重抓以 UI 為主，且策略是只補缺口。
- 單場重抓可同步執行；批次回填任務走背景執行。
- API 第一版以服務 UI 為主。

第一版安全規則：

- 不做帳號制與角色權限。
- 採單一密碼保護整個 UI 與 API。
- 形式為單頁輸入密碼後進入系統。
- 密碼保護層可在主功能完成後補上，但不可遺漏。

資料品質與 QA 規則：

- 預期馬匹數採雙重比對：`horses_v2` 與 HKJC 當場頁面。
- 若不一致，優先信 HKJC 當場頁面。
- 退出馬或未完成賽事馬匹仍計入預期馬匹數。
- 特殊名次值需保留原文欄位，不強制轉整數。
- `success / partial / failed` 判定必須完整落地。
- 黃金測試樣本必須全部跑通。

執行策略要求：

- 先讀 docs，再審視現有專案結構與可重用模組。
- 先完成資料模型、抓取器、解析器、入庫與回填主流程，再補齊 API 與 UI。
- 開發過程中盡量自主完成，不要把一般性實作決策回拋給人。
- 若遇到未確認事項，只能採最保守、最不破壞資料、最不擴張 scope 的方案繼續。
- 若遇到真正阻塞開發的外部因素，再整理成最小問題集合回報。

完成標準：

- 新增資料表已建立
- 馬匹歷史索引可運作
- 場次任務生成可運作
- `incident_report` 可獨立打通
- `running_comment` 可獨立打通
- `sectional` 可獨立打通
- 主回填腳本可運作
- 手動重抓入口可運作
- 重跑不重複寫入
- registry 狀態可追蹤
- QA 規則可驗證
- `partial / failed` 判定完整落地
- 黃金測試樣本全部跑通
- UI 主要頁面可用
- UI 所需 API 全齊

請現在開始執行，並以最小風險、最小假設、最不破壞既有資料的方式，按文件規格完成第一版。
